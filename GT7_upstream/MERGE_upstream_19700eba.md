## Correction after run 359 (24 Sep, evening)

The buffer-side GT_SOFT_CLAMP scan was listed as "dropped with the old buffer manager". That was
wrong: it lived in the binding scan, not in the old manager. Without it, run 359 committed 9.70 GiB
of arena memory (three tail descriptors of 2.3-3.7 GiB over memory that is not GPU-mapped) and died
at t=65s on `vk::Result=ErrorOutOfDeviceMemory` in `EnsureResident`. Restored in `f540244b` on the
new BindBuffers and BindVertexBuffers: guest floor, dword alignment, 256 MB tail cap with its
GPU-mapped prefix, the size-0 survivor, and the vertex-range size-0 / >1 GB guards. Not restored:
the three checks against per-buffer backing sizes, which the arena does not have.
Run 359 was not a clean-upstream baseline either: it changed the upstream code AND removed lab
guards in the same step.
